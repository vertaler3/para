## 1. Окружение и как здесь работает вёрстка

- `git clone` → `docker compose up --build -d` → `http://localhost:8080`. В контейнере — **живые демо-данные** из `fixtures.sql` (5 аккаунтов): моки не нужны.
- **Важно:** CSP-шаблоны компилируются Drogon-ом в бинарь. Изменение шаблона видно после пересборки: `docker compose up --build -d` (~1 мин). Планируй вёрстку порциями: собрал экран целиком → одна пересборка.
- Новый шаблон: файл `views/xxx.csp` создаёшь сам, класс генерирует `drogon_ctl create view views/xxx.csp` (на сборке — `drogon_create_views`, рекурсивно). Синтаксис drogon v1.9.14: вывод переменной — `[[ имя ]]` или `<%c++ $$ … %>`; **автоэкранирования нет** — пользовательские данные экранирует сервер или `HttpViewData::htmlTranslate` (образец — `views/partials/head.csp`). Синтаксиса `{{ }}` в v1.9.14 НЕ существует (упоминание в 02 §6.4 устарело) — литерал попадёт в HTML как есть.
- DevTools → режим мобильного устройства, ширина **360 px** — рабочая точка всего интерфейса; проверяй на ней постоянно, десктоп — адаптив того же DOM.
- htmx и Alpine.js планируются вендоренно в `static/vendor/` — пока каталог пуст, каркас на них не опирается (Р-16); вендоринг — отдельная задача с проверкой лицензий (AGENTS §5.4). **Никакого npm и внешних CDN.** Шрифты Inter — в `static/fonts/` (Manrope текущим брифом не используется, Р-16).

## 2. День 1 (вместе с BE): токены и база стилей

## 4. Как собирать один экран (цикл)

1. Открыть вайрфрейм и спеку экрана в 03 §4.x — они самодостаточные: собирай без импровизации.
2. Разметка в `views/*.csp` из готовых компонентов `app.css`; одна primary-кнопка на экран; тап-зоны ≥ 44 px (03 §6.2).
3. Подключить данные: htmx-атрибуты на живой эндпоинт; для фрагментов — `HX-Request` (BE отдаёт HTML-фрагмент тем же обработчиком).
4. Включить интерактив по минимуму: Alpine для локальных состояний (аккордеон, выбор слота, dialogs); сервер решает всё остальное.
5. Четыре состояния (03 §5): скелетон загрузки, пустое состояние с текстом «что делать», ошибка с ретраем, офлайн. **Проверяются отключением сети в DevTools.**
6. Проверки экрана (чек-лист раздела 9) → коммит `fe/экран-…`.

## 5. Правила htmx / Alpine / ошибок

- State-changing — только POST/PUT/DELETE через формы/htmx; GET — чтение (02 §5.1).
- Ошибки валидации/бизнес-правил приходят HTML-фрагментом (для htmx) или JSON `{"error":{…}}` — показывай их в том месте формы, где возникли; 409 «слот только что заняли» — inline-предупреждение + перерисовка сетки (03 §4.9.5).
- Deep link каждого уведомления ведёт к объекту (карточка переноса, таймлайн заявки) — не «в раздел».
- Диалоги подтверждения (выход, отмена брони) — с `danger`-подтверждением, как в спеках 03.

## 6. PWA (после экранов ядра)

- `pwa/manifest.json` + `sw.js`: офлайн-кэш расписания и ленты, install-баннер (02 §2.4).
- Без сборочных шагов: файлы лежат как есть, подключение — `<link>`/регистрация SW в базовом шаблоне.
- Проверка: airplane mode → расписание открывается из кэша с пометкой «офлайн».

## 7. Ежедневный цикл (рутина)

1. Прочитать `AGENTS.md` → ветка `fe/экран-…`.
2. Промпты агентам — из 05 §4.2, каждый начинается с «Прочитай AGENTS.md в корне репозитория»; диалоги — в `docs/agents-log/` (критерий жюри №2).
3. Перед коммитом: `python3 -I tools/contrast_check.py` → 0 FAIL; визуальная проверка на 360 px.
4. Вечером — слияние с `main` (гейт: ctest + security_tests + contrast зелёные — их гоняет BE, но FE не сливает при красном).
5. Конец своего куска: обновить свою часть AGENTS.md (статус экранов, открытые вопросы про вёрстку).

## 8. Если эндпоинта ещё нет

- Собери шаблон полностью со скелетоном и пустым/ошибочным состоянием, данные — захардкоженный фрагмент с пометкой `<!-- TODO(api): /v1/… -->`.
- Запись в AGENTS.md → «Открытые вопросы»: какой эндпоинт ждёт экран — BE увидит и приоритизирует.
- Не выдумывай поля контракта: структура данных = то, что отдают фикстуры/02 §5.2; расхождение — в `docs/decisions.md`, а не в тишине.

## 9. Чек-лист сдачи экрана (принят в дорожке)

- [ ] Собран по вайрфрейму 03 без импровизации; одна primary-кнопка
- [ ] Четыре состояния работают (проверено отключением сети)
- [ ] 360 px — без горизонтального скролла; тап-зоны ≥ 44 px
- [ ] Контраст: `contrast_check` 0 FAIL; тёмная тема не разваливается

- [ ] Бейдж «концепт для хакатона» на месте; никаких внешних CDN
- [ ] Коммит с экраном включает его состояния — одним коммитом
