**Календарь:** даты этапов в 05 §3 — оценка; фактические даты фиксируй в AGENTS.md, номер этапа важнее даты.

## 3. Ежедневный цикл (рутина каждой сессии)

1. Прочитать `AGENTS.md` → ветка `be/этап-…`.
2. Задачи агентам — промптами из 05 §4.2, каждый начинается с «Прочитай AGENTS.md в корне репозитория»; диалог — в `docs/agents-log/`.
3. Перед каждым коммитом: `cmake --build build-tests && ctest --output-on-failure` — зелёный.
4. Вечером — слияние `main` и FE-ветки: гейт = ctest + `security_tests` + contrast 0 FAIL.
5. Конец этапа: обновить AGENTS.md (статус, открытые вопросы) — иначе этап не закрыт.

## 4. Э2 — профиль (BE-часть)

- `GET /v1/me` — профиль из `profiles` по сессии (login уже отдаёт cookie).
- `GET/PUT /v1/notifications/settings` — три тумблера, `quiet_hours_json`, `theme`, `onboarding_json` (закрытые шаги онбординга С5).
- **Введи `OwnershipGuard` как сервис** (02 §6.3) — дальше все path-id эндпоинты идут через него; правило код-ревью: «контроллер с path-id обязан вызвать guard».
- Проверка: PUT настроек меняет строку `settings` своей сессии; curl без cookie → 401.

## 5. Э3 — расписание (BE-часть)

- `ScheduleCtrl`: `GET /v1/schedule/today`, `/week` (query `offset`), `/changes` (`days=7`) — выборки по `idx_schedule_group_time` / `idx_schedule_group_status`.
- `ScheduleCache`: `drogon::CacheMap<group_id, WeekModel>` TTL 60 с; инвалидация — в той же транзакции, что и перенос (пригодится Э6).
- `IcsCtrl` + `IcsBuilder`: `GET /ics/{token}` (VCALENDAR из `schedule_events` группы + `session_plan`), `POST/DELETE /v1/ics/token` — приватная ссылка 5.4.
- Проверка: сегодня/неделя отдают расписание группы Ани (фикстуры); ICS открывается в календаре телефона; отзыв токена → 404.

## 6. Э4 — успеваемость (BE-часть)

- `GradesCtrl`: `GET /v1/grades`, `/grades/summary` (средний балл, прогресс), `/grades/{id}` **через OwnershipGuard** (прямая цель security-теста), `GET /v1/exams` (экран «Сессия» из `session_plan`).
- Проверка: сводка Ани — пустая успеваемость (состояние FE «пусто»), у Марка — дедлайны/пересдача.

## 7. Э5 — заявки и справки (BE)

- `AppWorkflow` (сервис): матрица переходов статуса `submitted → accepted → in_progress → need_info|ready → issued`, недопустимый переход → **409**; каждое изменение пишет `application_events` (таймлайн).
- Эндпоинты: `POST/GET /v1/applications`, `PUT /v1/applications/{id}` (автосохранение черновика, только draft), `GET /v1/applications/{id}` (+таймлайн), `POST /v1/applications/{id}/messages`, staff: `GET /v1/staff/applications` (очередь), `POST /v1/staff/applications/{id}/status` (StaffFilter: не staff → 403).
- `PdfBuilder` (libharu): `GET /v1/applications/{id}/pdf` — владение + статус `ready|issued`; встроенный TTF-шрифт для кириллицы, диагональный штамп «ДЕМО · вымышленные данные».
- Проверка: юнит-тесты AppWorkflow (все переходы); интеграция С2 и С7; PDF начинается с `%PDF-` и содержит штамп; чужой id → 403.

## 8. Э5а — бронь аудитории (BE, 1 вечер)

- Миграция `0005_rooms.sql` (02 §4.1): `rooms`, `room_bookings`, **частичный UNIQUE-индекс** `idx_bookings_active` — двойная бронь невозможна на уровне БД.
- `RoomsCtrl`: `GET /v1/rooms`, `GET /v1/rooms/{id}/slots` (слоты дня: свободно/занято/ваша бронь), `POST /v1/rooms/{id}/bookings` (пересечение проверяется на сервере **и** индексом), `GET /v1/room-bookings`, `DELETE /v1/room-bookings/{id}` (своё), `POST /v1/staff/rooms/{id}/block` (блокировка; активная бронь снимается → уведомление автору).
- Фикстуры: 3 аудитории, брони для демо.
- Проверка: бронь → повторная бронь того же слота другим клиентом → 400; конфликт «только что заняли» → 409 для FE-сетки; `DELETE` чужой брони → 403 (шаг 8 security-теста).

## 9. Э6 — уведомления (BE)

- `NotifyDispatcher`: три тумблера из `settings`, тихие часы (ночное → утренний дайджест; срочный перенос ближайшей пары — сразу), deep link каждого уведомления.
- Таймер trantor `runEvery` (раз в минуту): базовое напоминание «за 1 день» по `deadlines.reminded`, персональные `deadline_reminders` (02 §5.1).
- `WsCtrl` (`GET /ws`, 101 upgrade) — канал push; `POST /v1/staff/schedule/changes` — перенос/отмена/замена (`prev_*`-поля «было → стало») + авторассылка группе; `GET /v1/staff/dashboard` — счётчики очереди; объявления: `GET /v1/announcements`, `POST /v1/staff/announcements` (без push — только лента/дайджест).
- Проверка: перенос пары сотрудником → уведомления Ани и Олега (группа 1-ФМО) в обеих учётках; WS-событие приходит в открытый сокет; ночью — в дайджест.

## 10. Э8 — безопасность (BE, 1 вечер)

- `security_tests.cpp` — все 8 шагов из 02 §9.3 **зелёные** (включая 403 на чужую бронь).
- Сборки под `-fsanitize=address,undefined` — тесты проходят.
- Ревизия: CSRF-проверка на state-changing, лимитер, секреты только в env (`env.example` без значений), логи без паролей/токенов, cookie-флаги.
- Вывод security-теста сохранить в `docs/screens/` — приложится к PDF-отчёту (DoD №2).

## 11. Э9 — деплой прод-контура (BE, 1 вечер)

> Это **первый** деплой на VPS — перенесён сюда с Э1 (решение команды от 05.11): до этого этапа всё работает в локальном Docker. Пошаговая настройка сервера с нуля — памятка в чате от 05.11; ниже — контрольные шаги поверх неё.

1. VPS: docker compose, том `para-data`, `config.json` без секретов.
2. Nginx reverse proxy + TLS Let's Encrypt (`deploy/nginx.conf`), gzip, Cache-Control статики.
3. systemd `para.service` с харднингом и `Restart=always`.
4. `deploy/backup.sh` — cron каждые 6 ч: `sqlite3 … ".backup …"` + копия за пределы VPS.
5. Проверка из РФ **без VPN** с мобильного интернета; `/healthz` внешне 200.
6. AGENTS.md: записать фактического провайдера и команды.

- [ ] Секреты — в env; в коде/репо/браузере их нет

- Изменили API/DDL — сначала запись в `docs/decisions.md`, затем правка 02, затем `AGENTS.md`; уведомить FE (его шаблоны зависят от путей §5.2).
