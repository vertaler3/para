## Задача (промпт дословно, сокращена преамбула)

> Продолжая каркас para/ (шаг 3 Э1, гайд-бэкенд раздел 2, строка «Первый вечер — early check»), создай Docker-контур:
> 1. Dockerfile — по спецификации 02 §8.1: multi-stage; build-стадия FROM drogonframework/drogon:1.9.14 (apt-get install ninja-build ccache, cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release, cmake --build build -j"$(nproc)"); runtime-стадия FROM ubuntu:24.04 с apt-пакетами libsqlite3-0 libssl3t64 libargon2-1 ca-certificates sqlite3 tzdata; COPY бинаря и views/static/sql; mkdir /opt/para/data с владельцем 10001; WORKDIR /opt/para; USER 10001; EXPOSE 8080; ENTRYPOINT ["/opt/para/para", "--config", "/etc/app/config.json"].
> 2. Необходимые дополнения к спецификации: COPY config.json в /etc/app/config.json (ENTRYPOINT его читает, а в 02 §8.1 копия не описана — это ожидаемое отклонение, запиши его в docs/decisions.md); если бинарь линкуется динамически с libdrogon/libtrantor — добавь их копирование в рантайм или переведи на статические цели (что выбрал в шаге 2 — учти). Отклонение фиксируй в docs/decisions.md.
> 3. .dockerignore: .git, build/, data/, docs/, .DS_Store. 4. docker-compose.yml: один сервис para (build: .), ports "8080:8080", named volume para-data:/opt/para/data, restart: unless-stopped. Комментарий «запуск демо: docker compose up --build». 5. Коммит («Э1: шаг 3 — Dockerfile multi-stage и docker-compose»).

## Что не сработало (ошибки и как пойманы)

1. **Arm64/rootfs-несовпадение**: без `--platform` стадия `ubuntu:24.04` резолвилась в нативную arm64, amd64-бинарь падал — `rosetta error: failed to open elf at /lib64/ld-linux-x86-64.so.2` (exit 133, контейнер в crash-loop). Поймано `docker logs` после `compose up`; фикс — `FROM --platform=linux/amd64` в обеих стадиях (Р-4 п.5).
2. **Недостающие зависимости из libdrogon.a**: после пина платформы — `error while loading shared libraries: libcares.so.2`; полный `ldd` показал 5 библиотек (c-ares, jsoncpp, libpq, mariadb, hiredis), вшитых статическим архивом Drogon. Промежуточная попытка копировать все пять `.so` привела к следующей ошибке — у `libpq.so.5.14` транзитивный замысей (`libgssapi_krb5.so.2`, `libldap-2.5.so.0`); при этом `libldap-2.5-0` в noble **не существует** (проверено установкой в ubuntu:24.04: `libldap-2.5-0: NOT FOUND`, а `libldap2` даёт другой soname). Итоговое решение — apt-пакеты с совпадающими soname (`libc-ares2 libjsoncpp25 libpq5 libmariadb3` — каждый проверен установкой: OK) + копия только `libhiredis.so.0.14` из build-образа (в noble hiredis 1.2 с soname `.so.1.2.0`). Р-4 п.6.
3. **`--config` из ENTRYPOINT игнорировался бы**: main.cpp из шага 2 не разбирал argv (Drogon сам не парсит) — приложение искало бы `./config.json` в WORKDIR `/opt/para` и поднялось бы без слушателя. Поймано чтением кода до запуска; main.cpp дополнен минимальным разбором `--config` (Р-4 п.3).
4. **ERROR-спам в логах при USER 10001**: Drogon создавал дефолтный `uploads/tmp/…` в root-owned `/opt/para` → `Error 13 … Permission denied` (Utilities.cc) на каждом старте (healthz при этом работал). Поймано просмотром `docker logs` после зелёного healthz; фикс — `"upload_path": "data/uploads"` (том с владельцем 10001), Р-4 п.7. Побочный след этой ошибки: каталог `uploads/` остался в рабочей копии хоста (контейнеры шага 2 монтировали `$PWD`) — убран в рамках исправлений по ревью.

## Что правлено вручную

Ничего; все итерации — правки агента, зафиксированные в Р-4.
