## Находки шага

1. **Коллизия имён `Result`** (`namespace para` + `using namespace drogon::orm`): неквалифицированный `Result` в лямбдах — это `para::RoomsService::Result`, не `drogon::orm::Result` — сборка падала с бессвязными ошибками. Лечение — как в `ScheduleService.cpp`: типы строк выборок полностью (`const drogon::orm::Result&`), комментарий в шапке .cpp.
2. **EXPLAIN QUERY PLAN:** запрос слотов со `status IN ('booked','blocked')` даёт `SCAN room_bookings` + TEMP B-TREE — частичный индекс неприменим (условие `WHERE status='booked'` не имплицируется). Итог шага: сетка строится по активным броням `status='booked'` (это и есть «чужая активная бронь» 02 §5.2) → `SEARCH ... USING INDEX idx_bookings_active (room_id=? AND starts_at<?)`, ORDER BY покрыт индексом. Отображение блокировок сотрудника (`blocked`) — шаг 3 Э5а (гайд BE §8), там же пересматривается выборка; юнит-тест фиксирует контракт шага 1 (blocked-строка не занимает слот в сетке шага 1).
3. Rest-хелпер часа (вместо comma-expression со snprintf) — читаемость, без изменения поведения.
