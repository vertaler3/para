**Решения.**
1. **Таблицы — `inline constexpr Entry[]` с выводом размера** (не `std::array` с
   CTAD): GCC 11 образа не вывел тип из вложенных brace-списков (ошибка компиляции
   на первом же прогоне — см. «Ошибки»); размер 253 выводится инициализатором и
   косвенно проверяется static_assert паритета keyset.
2. **Гарантии на компиляции, не на доверии:** static_assert строгой
   отсортированности (двоичный поиск), полноты en/zh относительно ru, непустоты
   значений — поймали реальный баг порядка уже на этом шаге (блок exam.* стоял
   перед error.*: «error» < «exam» по второму символу 'r'<'x' — см. «Ошибки»).
3. **Резолв — чистые строки без drogon-зависимости** (namespace para::i18n, не
   para::models): словарь доступен юнит-тестам шага 7 и контроллерам шага 3;
   cookie/заголовок передаёт вызывающий (HttpRequest::getCookie / getHeader —
   шаг 3). q<=0 исключается (RFC «not acceptable»), мусорный q — вес 1 (default
   weight), «*» не резолвит язык.
4. **Состав словаря по инвентарю i18nScope, вне словаря — осознанные
   исключения** (зафиксированы в шапке i18n.h): staff.csp, API-ошибки, контент
   БД, PDF, бейдж концепта — по-русски. Вордмарк «пара» не переводится (как
   логотип); автонимы сегмента языка lang.ru/lang.en/lang.zh («Рус | EN | 中文»)
   одинаковы во всех таблицах; app.title en/zh — «Para». Новые ключи 5.18 уже
   заведены: profile.language, a11y.langGroup, toast.langSaved/toast.failLang —
   шаг 3 не будет расширять словарь под сегмент.
5. **Формы множественного числа — тройки plural.*.{one,few,many}** для
   «N пар/событий/баллов/дисциплин»: ru-морфология остаётся на вызывающем
   (существующий plural() в grades.csp), en/zh — one/few/many совпадают
   («classes»/«节课»); композицию («Сегодня · N пар», «За ночь: N событий»)
   соберёт шаг 3.

**Ошибки.**
- Первый прогон сборки: CTAD `std::array kRu{{…}}` не вывелся в GCC 11
  («couldn't deduce template parameter ‘_Tp’», каскадом упали static_assert t())
  → перевёл таблицы на constexpr C-массивы неизвестной границы.
- Второй прогон: static_assert отсортированности поймал мой промах — блок
  exam.* шёл перед error.* (посчитал «exa» < «err» по третьему символу, а решает
  второй: 'r' < 'x'); перенос блоков подтверждён независимой проверкой порядка
  скриптом (все три таблицы: 253 ключа, нарушений нет, паритет ru=en=zh,
  дублей нет) — затем сборка зелёная.
- В одноразовой мини-проверке дважды правил макрос CHECK/запуск: `g++` в образе
  отсутствует (есть `g++-11`), и `(void)0 : printf` — несовместимые операнды
  тернарника → `(void)printf`. Не влияет на код фичи.

**Решения.**
1. **Cookie para_lang ставит СЕРВЕР через мини-роут GET /lang, а не JS**
   (digest.frontendFacts: app.js никогда не пишет document.cookie — все
   cookie выдаёт сервер; прецеденты para_session/csrf). Мини-роут публичный
   (гость меняет язык на входе), GET без CSRF — матрица 02 §6.4
   (state-changing — POST/PUT/DELETE); значения ограничены ru|en|zh,
   SameSite=Lax держит cross-site GET, ошибочная cookie исправляется
   следующим кликом.
2. **Сохранение в settings.lang — PUT из app.js (прецедент темы,
   app.js:3190–3201)**, не записью из мини-роута: тот же путь валидации
   applyPatch/UPSERT; гость (authedSettings=false после 401) пропускает
   PUT — язык живёт в cookie. Порядок: await PUT → при сбое тост и без
   перехода; успех → переход на /lang (302 назад) — страница перерендерится
   на новом языке (переводы — серверный словарь, локально их нет).
3. **Список кодов ru|en|zh живёт в трёх местах, сознательно**:
   CHECK миграции 0008 (БД), isValidLang сервиса (слой БД не тянет
   models/i18n.h ради трёх констант), i18n::langFromCode (мини-роут и
   резолв). Синхронность держит юнит-тест (перебор ok/bad кодов против
   applyPatch) и живой смок.
4. **Три юнит-теста с собственными схемами settings дополнены колонкой
   lang** (notify_dispatcher/reminder_service/staff_step): их фикстуры
   копируют колонки settings из миграций — аддитивное обновление по
   прецеденту появления theme/onboarding_json; сценарии самих тестов не
   изменены.
5. **Подсветка активного языка на шаге 2 — клиентская по cookie para_lang**
   (markLang до ответа сервера; после GET настроек уточняется s.lang);
   канонической станет серверная подсветка шага 3 (view-данные сегмента).

  (скриншоты zh на 360px) — за финальным браузерным проверяющим,
  постановкой на этот шаг не кладётся.

**Решения.**
1. Стек — дословно из постановки, Arial исключён: покрытие Latin/Cyrillic
   удерживают Inter (self-hosted subsets) + generic sans-serif, а у
   Microsoft YaHei Latin/Cyrillic есть и так; лишнее звено между Inter и
   CJK-шрифтами задачу fallback не улучшает.
2. CJK не вендорится — решение уже принято рамкой фичи (AGENTS §5.4:
   сторонний ассет только после лицензионной проверки с записью в
   decisions.md; мегабайтные CJK-файлы вне объёма) — новой записи Р-N не
   потребовалось, комментарий в tokens.css фиксирует выбор на месте
   использования. Doc-синхронизация фичи (CJK-примечание 03 §2.3) —
   отдельный шаг фичи; цепочку там указать по НОВОМУ токену.
3. (б) не дублировал: реализация шага 3 (head.csp, Р-16) уже даёт
   `<html lang>` по view-данным; шаг 4 = факт-проверка на живом сервере.

**Ошибки.** Нет: сборка/тесты/смок зелёные с первого прогона; правка
одного CSS-файла не касается C++/шаблонов (пересборка подтвердила).
