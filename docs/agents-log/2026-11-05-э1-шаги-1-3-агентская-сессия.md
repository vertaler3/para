## Ошибки и правки (итог по сессии; детали — в пограничных журналах)

1. **Тег `drogonframework/drogon:1.9.14` не существует** → проверка Docker Hub API, валиден `v1.9.14`; зафиксировано в Р-2, использовано в Dockerfile. Уточнение к 02 §8.1 отложено до правки документа (сейчас — только decisions).
2. **arm64-хост резолвил `ubuntu:24.04` в arm64**, amd64-бинарь падал (`rosetta error … ld-linux-x86-64.so.2`, exit 133) → пин `--platform=linux/amd64` в обеих стадиях (Р-4).
3. **Неполная проверка линковки на шаге 2** (grep по ssl/sqlite) → полный `ldd` на шаге 3 выявил 5 вшитых зависимостей; честная поправка в Р-4 п.4. Урок: зависимости бинарника перечислять полным `ldd`.
4. **Транзитивный замысей `libpq.so.5.14`** (krb5/ldap-2.5/gnutls/sasl; `libldap-2.5-0` в noble отсутствует) → вместо копии пяти `.so` — apt-пакеты с совпадающими soname + копия только `libhiredis.so.0.14` (Р-4 п.6).
5. **`--config` из ENTRYPOINT игнорировался бы** (Drogon argv не парсит) → минимальный разбор `--config` в `main.cpp` (Р-4 п.3; файл общий — владелец BE по §5.8).
6. **ERROR-спам `Permission denied` при старте под uid 10001** (дефолтный `uploads/` в root-owned `/opt/para`) → `"upload_path": "data/uploads"`, 0 ERROR в логах (Р-4 п.7).
7. **Пропуск §5.7: журнал не вёлся по ходу сессии** → пограничные журналы созданы пост-фактум (`cc37ab3`), факт пропуска помечен в каждом; этот сводный файл — вкладка летописца workflow.
