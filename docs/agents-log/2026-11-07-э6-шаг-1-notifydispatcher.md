## Сделано

- **`src/services/NotifyDispatcher.{h,cpp}`** — единая точка создания уведомлений (02 §4.5: «пишет уведомление в БД — источник истины — и пушит живым соединениям»; гайд BE §9). `notify(db, NotifyInput, cb)`:
  1. **Настройки** — `SettingsService::load` (тот же SELECT, что GET /v1/notifications/settings; load уже fail-closed к дефолтам DDL — Э2 шаг 3);
  2. **Решение** — чистая функция `decide(settings, type, urgent, minuteOfDayUtc)`: тумблер типа (notify_schedule/notify_deadlines/notify_applications 02 §4.1) выключен → `SuppressedByToggle`; `announcement` — всегда `Sent` (без тумблера, мимо тихих часов и push — 01 §4.5 «решение по каналам» и 01 §5.6 «поэтому в тихие часы не попадают»); ночное не-срочное → `DeferredToDigest`; иначе `Sent`;
  3. **Sent** → INSERT в `notifications` (created_at/read_at — DEFAULT/NULL по DDL 0004; body пустая строка → SQL NULL через `std::optional`) и **после** записи — WS-push (точка интеграции `setPushFn`: колбэк пушит живому соединению, если оно есть; реестр — шаг 3, колбэк по умолчанию не установлен). Ошибка БД → `Error` — fail-closed: ни строки без push, ни push без строки. `DeferredToDigest` → очередь `takePendingDigest()`/`pendingDigestCount()` (шаг 2 разберёт утром); `SuppressedByToggle`/`Error` → ничего.
- **Правило тихих часов** (`inQuietHours`, 02 §5.6; 01 §5.6): интервал `[from,to)` из `quiet_hours_json` (дефолт DDL `{"from":"23:00","to":"07:00"}`; синонимы `start`/`end`), переход через полночь, `from == to` — пустой интервал, невалидный JSON → не задерживаем. **Срочность** (`isUrgentSchedule`): type=schedule и `eventStartsAtUtc` начинается в течение 24 часов (`0 ≤ starts−now ≤ 24ч`, граница включена) — тихие часы не задерживают; нечитаемая/некалендарная дата (обратная сборка строки, приём `validDate` Э5а) или дата в прошлом → не срочно (безопасный исход — отложить). Все времена UTC (как весь контур, 02 §4.3). **deep_link обязателен**: пустой → `Error` (инвариант «тап → карточка переноса / таймлайн заявки», 02 §4.1).
- **Границы шага (зафиксированы в шапке класса):** транзакционные вставки Э5 (смена статуса заявки `ApplicationsService`, блокировка брони `RoomsService`) остаются прямыми INSERT в своей транзакции — гейт Э5 требует атомарности «переход + уведомление» (AfterEventTx); их перенос в диспетчер — отдельное решение, не в этом шаге. Отложенные тихими часами уведомления живут во внутренней очереди (мьютекс) — персистентность дайджеста решит шаг 2.
- **`tests/unit/notify_dispatcher_test.cpp`** — 9 кейсов на временной SQLite (схема 0004: notifications с CHECK-словарём типов + settings): интервалы тихих часов (дефолт через полночь, односуточный, синонимы, невалидные); срочность (+3ч/ровно +24ч/+24ч+1с/в прошлом/нечитаемое/некалендарное/нет даты); `decide` — каждый тумблер, announcement мимо тихих часов, ночь/день; **e2e**: тумблер off → записи нет и push нет (у user 8 выключен только notify_deadlines — schedule доставляется: тумблер покрывает свой тип); тумблер on (строки settings нет — дефолты) → строка type/title/body/deep_link, read_at NULL, deep_link непустой, WS-push ровно 1 с корректным payload; ночное → `DeferredToDigest`, в БД 0 строк, в очереди 1 (все поля + deferredAtUtc), take забирает; срочное ночью (событие через 3 часа) → Sent + push, очередь пуста; announcement ночью → строка есть, push НЕТ, очередь пуста; пустой deep_link → Error; таблицы notifications нет → Error, без push (fail-closed). Время — тестовый шов `setClock` (день 12:00 UTC / ночь 23:30 UTC), RAII-сброс статиков между кейсами.
- **`CMakeLists.txt`** — `NotifyDispatcher.cpp` в `para` и `para-tests`; тест в `para-tests`.

## Находки шага

1. **ADL-коллизия `para::toString` с doctest:** свободный `toString(NotifyType)` в namespace para перехватывается unqualified-вызовом `toString(lhs)` внутри `doctest::detail::stringifyBinaryExpr` — CHECK над enum'ом компилировался в `const char* + const char*` (ошибка в doctest.hpp:1266, «required from notify_dispatcher_test.cpp»). Лечение: функция переименована в `notifyTypeName` (и `notifyTypeFromString`), причина зафиксирована комментарием в заголовке — ловушка для всех будущих enum'ов в para.
2. **doctest 2.5.3 требует потокового вывода для CHECK над enum'ами** — добавлены `operator<<(std::ostream&, NotifyType/NotifyOutcome)` в тестовом файле (до этого — та же ошибка строки 1266 для NotifyOutcome).
3. Окружение базового образа drogonframework/drogon:v1.9.14 беднее сборочного контура проекта: нет `libargon2-dev` и `fonts-dejavu-core` (их ставит Dockerfile проекта) — доучтено при подъёме одноразового контейнера.
