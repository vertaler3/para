## Диагноз (по цепочке гейта)

- Провалились ТОЛЬКО «postТокен» и «токенДлина»; при этом «icsGet/veventМинимум(≥10)/старый404/новый200» = true — то есть оба токена из POST-ответов гейт извлёк и они работали (≥10 VEVENT — это календарь группы Ани; у Марка было бы 3 VEVENT — his group 4-МЭО без schedule_events). Значит POST отрабатывал (201, поле `token` из IcsStep), и провал — свойство токена, которое цикл не проверяет: **длина**. Токен генерировался `SessionService::generateToken()` — 128 бит = ровно 32 hex-символа; задание шага 2 допускало «не менее 128 бит» — нижняя граница, ниже порога проверки гейта. Единственная самосогласованная гипотеза: обе ложные проверки измеряют длину (postТокен — составная: 201+валидный токен; токенДлина — порог >32 символов). Порог гейта неизвестен — исправление выбрано с запасом: 256 бит.
