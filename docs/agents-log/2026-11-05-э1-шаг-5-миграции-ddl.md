## Ошибки/уточнения, учтённые в ходе

- Команда проверки из промпта (`docker run … para-para:latest sqlite3 …`) зависала: у образа ENTRYPOINT — сам бинарь `para`, поэтому `sqlite3` передавался приложению как аргумент и оно поднимало event loop. Рабочий вариант — `docker run … --entrypoint sqlite3 para-para:latest …` (зафиксировано здесь для следующих шагов).
- `PRAGMA foreign_keys = ON;` в 0001 внутри транзакции раннера — документированный no-op SQLite (pragma не действует внутри BEGIN), ошибки не даёт: подтверждено фактическим прогоном раннера.

## Проверки

- Синтаксис каждого файла отдельно (образ para-para:latest, sqlite3 3.45.1): `docker run --rm -v …/sql:/sql:ro --entrypoint sqlite3 para-para:latest :memory: ".read /sql/migrations/000N_*.sql" ".tables"` — все 5 читаются без ошибок, каждая миграция создаёт ровно свои таблицы.
- Все 5 последовательно в одну :memory:-базу: 22 таблицы (21 + sqlite_sequence от AUTOINCREMENT), 12 idx_*, `PRAGMA foreign_key_check` — пусто.
- Реальный раннер на миграциях (контейнер drogonframework/drogon:v1.9.14, сборка в /tmp, конфиг с migrations_dir=/src/sql/migrations): приложение стартует, `/healthz` → «ok»; лог — «миграция применена» ×5; в БД `schema_migrations` = 5 версий, `user_version` = 5, 12 индексов, `foreign_key_check` пуст, `journal_mode` = wal.
- `ctest --output-on-failure` перед коммитом — 100% (para-tests, security_tests).
