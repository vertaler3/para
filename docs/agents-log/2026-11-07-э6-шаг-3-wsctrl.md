## Сделано

- **`src/services/WsRegistry.{h,cpp}`** — реестр живых соединений «user_id → connection» (02 §3.2 поток 3): в памяти процесса, под мьютексом (вызовы с IO-потоков drogon); несколько вкладок одного пользователя — несколько соединений, событие получают все. `add` (handleNewConnection), `remove` (handleConnectionClosed; дедупликация по указателю соединения — чужое/несуществующее/повторное remove — no-op, последний удаляет запись пользователя), `send(userId, payload)` — компактный JSON-кадр (`Json::StreamWriterBuilder`, indentation="") всем живым (`connected()`); мёртвые не считаются доставленными и лениво удаляются (страховка к обработчику закрытия); false — живых нет (событие не теряется: БД — источник истины).
- **`src/controllers/WsCtrl.{h,cpp}`** — тонкий WebSocketController: `WS_PATH_ADD("/ws", "LoginFilter", Get)` — «/ws» не в публичном списке фильтра, handshake требует cookie-сессию; `handleNewConnection`: user_id из атрибута «session» (SessionInfo, кладёт LoginFilter) → в context соединения (для чистки) → `WsRegistry::add`; fail-closed: атрибута нет → `conn->shutdown()` и без регистрации; `handleConnectionClosed`: userId из context → `WsRegistry::remove`; `handleNewMessage` — пустой (канал однонаправленный, ping/pong — фреймворк).
- **`src/main.cpp`** — связывание точки интеграции шага 1: `NotifyDispatcher::setPushFn([](userId, payload){ WsRegistry::send(userId, payload); })` до `app().run()` — колбэк обязан стоять до первого notify.
- **`tests/unit/ws_registry_test.cpp`** — 5 кейсов с фейком соединения: WebSocketConnection в v1.9.14 — абстрактный класс с виртуальными методами (WebSocketConnection.h) → наследник без сети копит кадры и умеет «закрываться»: пуш живому — один компактный JSON-кадр ровно с {type,title,body,deep_link} (обратный парсинг), несколько вкладок получают все и remove адресный, remove чужого/нулевого/повторного — no-op, мёртвое соединение не доставляется и лениво чистится (после send countOf=1), send без соединений/null payload/невалидный add → false.
- **`CMakeLists.txt`** — `WsCtrl.cpp` в `para`; `WsRegistry.cpp` в `para` и `para-tests`; тест в `para-tests`.

2. **drogon отдаёт 404 на WS-роут при запросе без Upgrade-заголовков** — проверка «без cookie → 401» обязана быть именно WS-handshake-запросом (с Connection/Upgrade/Sec-WebSocket-Key/Version); так и проверяет гейт (curl без cookie на handshake).
3. Шум trantor в логе при резком закрытии сокета клиентом: «FATAL Transport endpoint is not connected (errno=107) sockets::shutdownWrite» (Socket.cc:110) — процесс жив (healthz после — 200); класс шумов Э1-ревью («FATAL MULTITHREAD в логе старта»), не влияет.
4. Параллельно подтверждено: 401 без cookie приходит от LoginFilter ДО апгрейда (фильтр в цепочке WS_PATH_ADD) — тело в формате 02 §5.1 `{"error":{"code":"unauthorized",…}}`.
