## Находки шага

1. **Ловушка имён Result (повторение урока RoomsService.cpp:19):** внутри тела методов `LibraryService` имя `Result` резолвится в `para::LibraryService::Result` (class scope), а не `drogon::orm::Result` — первый прогон сборки упал («'begin' was not declared», итерация по Json-Result вместо строк); исправлено полным квалификатором `drogon::orm::Result` в трёх лямбдах, урок задокументирован в шапке .cpp.
2. **Ограничение поиска (честно):** LIKE в SQLite без ICU регистрозависим для не-ASCII — поиск по кириллице работает по точному регистру подстроки («Гущин» найдёт, «гущин» — нет). Контракт 02 §5.2 регистр не оговаривает; поведение зафиксировано в шапке LibraryService.h и теста. Тест на НЕ-совпадение в другом регистре сознательно не добавлен (не маскировать ограничение как контрактовое).
3. **PDF-тесты зависят от шрифта окружения:** два кейса PdfBuilder падают, если в контейнере нет fonts-dejavu-core (сам тест печатает подсказку «установи fonts-dejavu-core или задай PARA_TEST_FONT»); в drogon-образе шрифта нет (Dockerfile ставит его только в рантайм-слой). Прогоны с установленным шрифтом — зелёные; к тестовому Dockerfile-профилю (Э8/гейт) — учесть.
4. **Баг собственного fail-closed-кейса пойман тестами до коммита:** первая редакция фикстуры `Fixture(false)` создавала схему без данных — сервисы закономерно отвечали ok/NotFound, а не Error; введён второй параметр `withTables` (по образцу теста RoomsService) — fail-closed гоняется на БД без схемы.
