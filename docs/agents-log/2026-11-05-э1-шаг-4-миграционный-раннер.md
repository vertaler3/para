- **Дата:** 05.11.2026 · **Дорожка:** BE · **Инструмент:** агентская сессия в составе workflow шагов Э1
- **Промпт (суть):** «Прочитай AGENTS.md, гайд-бэкенд §2 (шаг 4), 02 §8.3. Выполни только шаг 4: сервис MigrationRunner (schema_migrations, транзакции на файл, PRAGMA user_version дублёром, fail fast), режим --seed для fixtures.sql с идемпотентностью, SQLite DbClient в config.json (WAL, /opt/para/data/para.db), вызов раннера в main.cpp до роутов, юнит-тест идемпотентности, коммит».

## Что сделано

- `src/services/MigrationRunner.{h,cpp}` — синхронный раннер на системной libsqlite3: создаёт `schema_migrations(version PK, applied_at)`, применяет `NNNN_*.sql` по возрастанию номера, каждый файл в `BEGIN IMMEDIATE … COMMIT` с записью версии (параметризованный INSERT); `PRAGMA user_version = max(числовые версии)`; WAL+synchronous=NORMAL; `--seed` — маркер `fixtures` в той же таблице (идемпотентность второго старта); ошибки — `MigrationError` → main падает с внятным логом (без деградации).
- `src/main.cpp` — разбор `--seed`, вызов раннера до `app().run()` (пути из `custom_config`).
- `config.json` — `db_clients` (sqlite3, `/opt/para/data/para.db`, WAL через `initialization_queries`) + `custom_config` раннера.
- `CMakeLists.txt` — `find_package(SQLite3)`, MigrationRunner в целях `para` и `para-tests`.
- `tests/unit/migration_runner_test.cpp` — идемпотентность (прогоны 1/2/3), дублёр user_version, WAL, откат транзакции по ошибке, `--seed` без файла, сортировка/фильтрация каталога.
- `docs/decisions.md` — Р-5 (транспорт раннера, маркер fixtures, WAL через initialization_queries, дублирование db_path в custom_config).

## Ошибки/уточнения ИИ, учтённые в ходе

- ИИ предлагал раннер поверх асинхронного DbClient — отклонено: пул создаётся только в `app().run()`, миграции шли бы уже после открытия порта; выбор зафиксирован в Р-5 (это и есть требование «до поднятия роутов»).
- WAL: предложенный ИИ путь «PRAGMA только в раннере» дополнен каноническим для Drogon 1.9.14 `initialization_queries` в config.json (проверено по исходникам тега v1.9.14: ConfigLoader.cc / Sqlite3Connection.cc).
- Первая сборка упала на линковке `-lSQLite::SQLite3`: find_package(Drogon) подкладывает drogon'овский FindSQLite3, создающий цель `SQLite3_lib` (не `SQLite::SQLite3`). CMakeLists поддерживает обе цели — `if(TARGET SQLite3_lib)` (Р-5, «Нюанс сборки»).
- Юнит-тест поймал дефект: установка `PRAGMA user_version` после цикла миграций отставала от schema_migrations при откате упавшего файла (тест «ошибка в файле откатывает транзакцию»: user_version 0 при применённой 0001). Исправлено — дублёр обновляется в той же транзакции, что и запись версии.
- Ninja в чистом образе нет (его ставит Dockerfile) — проверочный прогон шёл генератором Unix Makefiles.
