## Находки шага

1. **Ловушка Э5а повторилась** (`RoomsService::Result`): неквалифицированный `Result` в лямбдах с `using namespace drogon::orm` разрешается во вложенный `ScheduleChangeService::Result`/`StaffDashboard::Result` — каскад бессвязных ошибок компиляции. Лечение то же: все типы строк выборок полностью — `const drogon::orm::Result&`.
2. **Два недозахвата в глубокой цепочке** (`in` в commit-callback, `fail` в success-ветке UPDATE) — пойманы компиляцией, следствие длинной вложенной структуры; после рефакторинга в двухфазную (подготовка payload ДО транзакции, commit-callback — только invalidate+рассылка+201) цепочки стали короче.
3. **doctest 2.5.3 запрещает `||` внутри CHECK** (static_assert Expression Too Complex) — переписано на отдельные CHECK/CHECK_FALSE.
4. **Перенос вернул 200 вместо 201** — поймано E2E-проверкой ожидаемого кода: `newHttpJsonResponse` по умолчанию 200; для 201 — `setStatusCode(k201Created)` (как в Э5).
5. Юнит-тест уведомлений падал SQLITE_BUSY/0 строк: рассылка ФОНОВАЯ (201 не ждёт INSERT'ов) — чтение из второго sqlite-соединения сразу после 201 гонится за писателем; лечится поллингом с дедлайном (waitCount/waitPush) + busy_timeout — семантика «201 не ждёт рассылки» теперь отражена и в тестах.
6. E2E-контур с пулом 2 соединений + WAL: полные 21 проверка зелёные (см. ниже).
