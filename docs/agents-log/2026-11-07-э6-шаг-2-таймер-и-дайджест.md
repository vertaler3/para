## Сделано

- **`src/services/ReminderService.{h,cpp}`** — фазовый сервис тика (вся SQL здесь, параметризованная):
  - **(а) `basicDeadlineRound`** — окно `(now; now+24h]` по `due_at` при `reminded = 0` (02 §4 поток 4); параметры окна биндятся из C++ через `NotifyDispatcher::nowUtc()` — тот же тестовый шов времени, что и решение о тихих часах (ISO-сравнение лексикографично, единый формат DDL). Получатели: персональный дедлайн (`user_id` заполнен; он приоритетен, если заполнены оба поля) — владелец; групповой — `SELECT user_id FROM profiles WHERE group_id=$1` («всем студентам группы» — staff без профиля не попадает, 02 §4.1). Каждый получатель — через `NotifyDispatcher::notify` (type='deadline', title — заголовок дедлайна, body «Срок: <due_at>», deep_link `/deadlines`): тумблер и тихие часы применяются к каждому (ночное — в дайджест, 02 §4 поток 4). Когда исходы всех получателей известны — условный `UPDATE deadlines SET reminded=1 WHERE id=$1 AND reminded=0`. Ошибка БД на SELECT получателей/окна → фаза 0, без метки — следующий тик повторит.
  - **(б) `personalReminderRound`** — `deadline_reminders` c `remind_at <= now` и `sent_at IS NULL` (JOIN deadlines) → уведомление владельцу (body «Ваше напоминание — срок: <due_at>») → условный `UPDATE … SET sent_at=$now WHERE user_id AND deadline_id AND sent_at IS NULL` после факта рассылки.
  - **`runMinuteTick`** — линейный конвейер (а) → (б) → (в), без рекурсивных self-captures (урок Э5а); `TickStats` — статистика фаз; cb стреляет ровно один раз; guard `if (cb)` на всех cb (пустой колбэк из main.cpp легален).
- **`src/services/NotifyDispatcher.{h,cpp}` — расширение шага 1** (обратно совместимо): `toIsoUtc/nowIsoUtc` (единый формат DDL) и `flushDigest(db, cb)` — разбор очереди дайджеста: забрать очередь целиком (`takePendingDigest` — доставленные существуют ровно в одном экземпляре), сгруппировать по владельцу; владелец ВНЕ своих тихих часов (первый тик после их конца) → доставить разом, каждый элемент через `notify()` (повторная проверка тумблера — настройки могли измениться за ночь; тихие часы уже не отложат — тик проверил интервал); владелец ещё в тихих часах → группа возвращается в очередь (параллельно отложенные элементы не тронуты). Итог — `DigestFlush{delivered, held}`; завершение — счётчики users/items + atomic once (паттерн AppWorkflow::fire). Доставка запускает все notify, cb не ждёт завершения INSERT'ов.
- **`src/main.cpp`** — `drogon::app().registerBeginningAdvice([] { drogon::app().getLoop()->runEvery(60.0, [] { ReminderService::runMinuteTick(drogon::app().getDbClient(), {}); }); })` перед `app().run()`: advice срабатывает «immediately after the main event loop runs» (HttpAppFramework.h v1.9.14:277) — «после запуска приложения», когда существует `getLoop()`; `EventLoop::runEvery` — EventLoop.h:194. Логики в main нет — только регистрация (§5.5).
- **`tests/unit/reminder_service_test.cpp`** — 7 кейсов на временной SQLite (схемы 0003+0004+profiles, без FK): дедлайн за 24 ч → 3 уведомления (Аня, Олег — группа 1; Марк — персональный) type='deadline' с deep_link + reminded=1 у обоих + 3 push; повторный тик → 0 и без дубля; границы окна (ровно now+24h — входит; due_at=now — нет; в прошлом — нет и метка не ставится; reminded=1 заранее — мимо); персональный remind_at → уведомление + sent_at NOT NULL, повторный → 0 (remind_at в будущем — мимо); дайджест: ночь → held 2 (очередь сохранена, в БД 0), утро 07:00 → delivered 2 разом, очередь очищена, push 2, повторный flush → 0 (не шлётся), субкейс «тумблер выключили за ночь» → элемент извлечён и подавлен (в БД только чужая строка); `runMinuteTick` — конвейер (1+1+1, строки 2+1+1=4, метки, очередь пуста) и повторный тик → нули; ночная рассылка дедлайна → reminded=1 при 0 строк в notifications, утренний flush доставляет, повторный тик без дубля. Время — `NotifyDispatcher::setClock` (день 06.11 12:00 UTC / ночь 07.11 02:00 / утро 07.11 07:00).

## Находки шага

1. **`DbClientPtr` в заголовке без квалификатора** — `drogon::orm::DbClientPtr`, не голое имя (в NotifyDispatcher.h — квалифицировано; в первом варианте ReminderService.h пропустил).
2. **Свободный хелпер `fire` — только `const std::function&`**: захваченные по значению колбэки внутри немутабельных лямбд константны — `std::function<void()>&` не биндится.
3. Классическая опечатка лямбды-`finish` (`finished` не захвачен) и задвоенный закрывающий `// namespace` после крупной вставки — обе пойманы первой же сборкой.
4. `git fetch --depth 1 origin <pin>` ускоряет подготовку libharu в одноразовом контейнере в разы против полного clone; пин проверяется тем же `git rev-parse HEAD` (Р-12).
