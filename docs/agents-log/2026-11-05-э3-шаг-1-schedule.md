## Что сделано

- `src/services/ScheduleService.{h,cpp}` — вся SQL и логика (AGENTS.md §5.5, 02 §6.4): `groupOfUser()` — группа из `profiles.user_id` (three-state: Found/NotFound/Error — NotFound = staff без профиля → пустой ответ 200, Error → fail-closed 500, не «пустое расписание»); `today()` — полуинтервал `[день T00:00:00Z, день+1)` по `idx_schedule_group_time` (equality+диапазон+ORDER BY одним индексом); `week()` — 7 дней от понедельника недели с offset (±, `weekStart()` через `tm_wday`/`timegm` — UTC, формат дат как в фикстурах «…Z»); `changeList()` — статусы `('moved','cancelled','substituted')` фиксированными SQL-литералами по `idx_schedule_group_status` + окно `[today-(days-1), today+1)` (последние days календарных суток включительно; изменение будущей даты показывается в день её наступления, оперативное оповещение — push Э6); JOIN `disciplines` даёт карточке `discipline`/`code`. `teacher_id` в ответах НЕ отдаётся (гайд BE §5: «с Э6а добавится teacher_id — на этом этапе не закладывай»); `prev_room`/`prev_starts_at`/`prev_teacher_id`/`changed_at` — «было → стало» (prev_* — null, когда переноса не было). Формы ответов 02 §5.2: today `{date, events[]}`, week `{offset, from, to, events[]}`, changes `{days, changes[]}`; ключ события — `id`. today/week/changeList принимают `today` параметром (в контроллере — `todayUtc()`, в тестах — фиксированная дата; wall-clock в тесты не заходит).
- `src/services/ScheduleCache.{h,cpp}` — `WeekModel{groupId, from, to, events}` + `drogon::CacheMap<int64_t, WeekModel>` (API v1.9.14 сверено по заголовку в образе: `insert` c timeout, `findAndFetch`, `erase` — всё под мьютексом); TTL 60 с — семантика CacheMap «вытеснение в пределах TTL от последнего обращения»; `put` по живому ключу до истечения — no-op (`std::map::insert` не перезаписывает), поэтому попадание отдаёт закэшированную неделю; защита от смены недели в кэше — сравнение `from`/`to`. `invalidate(group_id)` — хук Э6 (инвалидация при переносе в контуре его транзакции). `instance()` — ленивый singleton на `app().getLoop()`: потокобезопасен в любом потоке — CacheMap ставит тикер через `runEvery` → `TimerQueue::addTimer` → `EventLoop::runInLoop`, который вне потока loop'а уходит в очередь (проверено по исходникам trantor в образе: EventLoop.h runInLoop, TimerQueue.cc:193, EventLoop.cc:318). Кэшируется только offset=0 (ключ — group_id); offset≠0 идёт в БД всегда.
- `src/controllers/ScheduleCtrl.{h,cpp}` — тонкий (94 строки на 3 метода): разбор query-параметров (`getOptionalParameter<int>`; отсутствует → дефолт offset=0/days=7 — days=7 по 02 §5.2; не число → 400 `bad_request`; days вне 1..31 → 400) + маппинг `Result` → 200 JSON либо 500 `{"error":{"code":"internal",…}}` через общий `api::errorResponse` (02 §5.1); SQL в контроллере нет. Все три маршрута в METHOD_LIST под `"LoginFilter"` — без cookie 401 от фильтра (публичные префиксы фильтра не включают /v1/schedule — сверено). path-id нет — OwnershipGuard не применим. `static/` и `views/` не тронуты.
- `CMakeLists.txt` — ScheduleCtrl.cpp в `para`; ScheduleService.cpp + ScheduleCache.cpp в `para` и `para-tests`; тест в `para-tests`.
- `tests/unit/schedule_service_test.cpp` — 8 тест-кейсов на временной SQLite (схема — колонки groups/disciplines/profiles/schedule_events миграций 0001/0002 без FK + оба индекса §4.2; данные копируют демо-неделю фикстур: ids 1–10 группы 1, два moved 04.11, cancelled 05.11 id 7; дополнения помечены: id 11 substituted 01.11, id 20 — событие группы 2, id 30 — вставляется в тесте кэша): арифметика дат (weekStart 02.11=понедельник, сдвиг ±недели, граница месяцев); groupOfUser студент/staff; today — только свой день, свой порядок по starts_at, чужая группа вне, форма события (JOIN дисциплина, нет teacher_id); staff — 200 пусто; week — offset 0/+1/−1 (10 событий ids 1–10, from/to), изоляция группы Марка; changes — 4 изменения в окне days=7, prev_room 3024→4210, prev_starts_at==starts_at у отмены, prev_teacher_id=6 у замещения, normal не включены, окна days=1/2; ScheduleCache — попадание (смена данных под живым кэшем не меняет ответ — контракт инвалидации Э6), invalidate → пересчёт (11), повторная инвалидация отсутствующего безопасна, offset=1 не берёт кэш, loop+кэш в выделенном потоке; ошибка БД (пустая схема) — ok=false по всем трём эндпоинтам и Error в groupOfUser (fail-closed → 500).

## Ошибки ИИ, пойманные и исправленные в ходе (все — компиляцией/тестами контейнера)

1. **Двойной move колбэка в цепочке `>>`** (латентный урок Э2 шаг 1, OwnershipGuard.cpp:56): в трёх цепочках SqlBinder стоял `[cb = std::move(cb)]` в первой лямбде и `[cb]` во второй — вторая замыкалась на move-из-пустого → `std::bad_function_call` (SIGABRT) на error-пути БД. Поймано юнит-тестом fail-closed («ошибка БД → 500») — 19/20 кейсов зелёных, кейс ошибки БД падал. Исправлено копированием `cb` в обе ветки (как в OwnershipGuard), комментарий в коде уточнён (move опасен именно в ПЕРВОЙ лямбде).
2. **FATAL «There is already an EventLoop in this thread»** (EventLoop.cc:84): деструктор trantor EventLoop не сбрасывает thread-local `t_loopInThisThread`, а статическая инициализация drogon (регистрация контроллеров через `app()`) создаёт EventLoop в главном потоке ещё до `main()` — доказано пробой `getEventLoopOfCurrentThread()` (loop=0x555… до любого теста). Создание `trantor::EventLoop` в потоке теста — FATAL/exit(-1). Исправлено: loop+CacheMap создаются в выделенном потоке (EventLoop в потоке loop'а, CacheMap::put/get/invalidate мьютексом — из любого потока); это же и прод-семантика (тикер реально крутится).
3. **JOIN молча отфильтровал событие группы 2** — тестовое событие id 20 ссылалось на `discipline_id=6`, отсутствовавший в тестовой таблице disciplines; добавлена дисциплина 6 (как в фикстурах). На прод-данных невозможно (FK), проявилось только в тестовой схеме без FK.
4. Квалификация типов в .cpp: внутри тел методов `ScheduleService::…` неквалифицированный `Result` разрешался во вложенный `ScheduleService::Result`, а не `drogon::orm::Result` — конфликт типов в лямбдах SqlBinder; исправлено явной квалификацией.
5. API-факты сверены по исходникам образа v1.9.14, не по памяти: сигнатура `CacheMap(loop, tickInterval=1.0, wheels, buckets, fnOnInsert, fnOnErase)`; `getOptionalParameter<T>` возвращает nullopt и при отсутствии, и при нечисловом — контроллер отличает их через `getParameter().empty()`; базовый образ не содержит ninja/g++ (только g++-11/clang++-14; ninja и libargon2-dev ставит наш Dockerfile) — в одноразовом контейнере ставились apt-пакеты.
