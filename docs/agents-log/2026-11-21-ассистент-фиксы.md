# 21.11.2026 — ассистент: фиксы по итогам живого аудита (ветка `final_fixes_v1`)

Аудит (20.11, 17 вопросов в чате под anya.demo, факты сверены с
`/v1/schedule/today`, `/v1/map/rooms`, sqlite) нашёл у ассистента 8 проблем.
Причина большинства — слишком мягкий системный промт и неполный контекст.
Правим две вещи: `ASSISTANT_SYSTEM_PROMPT` в `.env` и сборщик контекста
`AssistantService`.

## Шаг 1 — новый ASSISTANT_SYSTEM_PROMPT (para/.env, не в репо — §5.2)

Значение (одной строкой с `\n`-эскейпами, кавычки снимает `unquoteEnv`):

```
Ты — «Ассистент Пара», помощник студенческого портала «Пара» (концепт хакатона, данные вымышленные). Отвечай ТОЛЬКО по данным из контекста запроса; если нужных данных в контексте нет — скажи «в портале нет такой информации» и укажи реальный раздел портала, где это можно посмотреть.
НИКОГДА не подставляй данные пользователя вместо данных о других группах/событиях: вопрос о чужой группе/аудитории/событии, которого нет в контексте, — это «нет информации», а не расписание пользователя.
ПРОВЕРКА РЕШЕНИЙ: не проверяй и не переписывай решение целиком — только намёки («проверь единицы измерения во втором шаге»), наводящие вопросы и похожие примеры другой формулировки. Никогда не говори «ваш расчёт верен»; если видишь вероятную ошибку — укажи, на какой шаг посмотреть, без готового итога. Считай аккуратно; если сомневаешься в точности — так и скажи.
ВРЕМЯ: пиши время ровно так, как оно записано в контексте (как в остальном интерфейсе портала), БЕЗ перевода часовых поясов и без сдвигов.
НАВИГАЦИЯ: называй только реально существующие разделы портала: «Сегодня» (дашборд), «Расписание» (+ сегмент «Неделя», ссылка «Забронировать аудиторию»), «Успеваемость», «Заявки» (+ «Новая заявка»), «Профиль», «Библиотека», «Столовая», «Карта», «Люди», «Зачётка», «Рейтинг», «Стол сотрудника» (только для сотрудников). Никогда не отправляй в разделы «Помощь» или «к администрации» — их нет в портале.
Кратко (1–5 предложений), дружелюбно, язык = языку вопроса; персональные данные других студентов не раскрывай; без markdown-таблиц.
```

Отличия от старого (полный разбор — ниже в «находках»): жёсткое «никогда
"ваш расчёт верен"», явный запрет подмены чужих групп данными пользователя,
время без перевода поясов, навигация только по реальным разделам портала.

## Шаг 2 — AssistantService (контекст)

1. **Время — как в UI, без UTC→МСК.** Раньше `mskTime`/`mskDateTime`
   сдвигали всё на +3 ч: модель говорила «13:00» там, где расписание
   показывает «10:00» (аудит 20.11, Q1; дедлайн 30.11 18:00Z → «21:00»,
   21:00Z → «01.12 00:00», Q2). Заменены на `portalTime`/`portalDateTime`
   (форматирование без смещения), «сегодня» — `todayUtc()` вместо
   `todayMsk()`, группировка дня — `isoDay()` (UTC-календарь портала, тот же
   «сегодня», что в `/v1/schedule/today`). Заголовок контекста теперь
   «время — как в интерфейсе портала, без перевода поясов».
2. **Аудитория из вопроса → карта в контексте.** `roomQuery(message)`
   извлекает номер вида «1207»/«Б-204»/«в-216» (0–2 буквы + дефис + 3–4
   цифры, буквы → верхний регистр); если найден — в контекст добавляется
   секция «Аудитории по твоему вопросу (из карты портала)» с результатом
   того же LIKE-поиска, что `GET /v1/map/rooms?q=…` (kRoomSql, экранирование
   LIKE как в MapService, JOIN buildings, floor/kind). Закрывает находку
   «где аудитория 1207?» → «нет информации» при живой карте (Q3).
3. **«Расписание твоей группы» — явно.** Секции контекста переименованы в
   «Расписание твоей группы на сегодня/завтра» + строка «Ниже — только твои
   данные… данных о других группах в этом контексте нет». Вместе с промтом
   закрывает подмену: вопрос про 4-МЭО отвечался парой самой Ани (Q14 —
   по БД у 4-МЭО в пт была Эконометрика 14:00 В-216, ассистент же назвал
   философию 3105 группы 1-ФМО).

## Шаг 3 — юнит-тест (`tests/unit/assistant_service_test.cpp`)

Новый кейс «контекст — аудитория из карты и только своя группа»:
`roomQuery` («1207»/«Б-204»/«в-216»→«В-216»/«у-204»→«У-204»; пусто для
вопросов без аудитории), `mentionedGroup` («4-МЭО», «1-фмо»→«1-ФМО»; пусто
для прочих), `portalTime("…T10:00:00Z") == "10:00"` (не «13:00») и
`portalDateTime`; живой чат на фикстурах: «Где аудитория 1207?» → в промте
есть «1207 — Корпус Б» и «этаж 2»; вставленная пара-маркер группы 2 сегодня в
12:00 Z отсутствует в контексте Ани и присутствует у Марка; вопрос о чужой
группе («пары у группы 4-МЭО…») → в промте «Твоя группа — 1-ФМО» и
предупреждение «группа 4-МЭО — это НЕ твоя группа … НЕ подставляй»;
«Проверь моё решение задачи…» → блок «проверить его решение … наводящий
вопрос», а «проверь расписание» маркер не включает; без номера аудитории
секции карты нет. Обновлён ассерт соседнего кейса на метку «Расписание твоей
группы».

## Раунд 2 (та же сессия) — почему одного промта не хватило

Живой прогон 21.11 после раунда 1 показал: время/карта/навигация — ок, но
yandexgpt-lite по-прежнему подменял чужую группу своей («Во сколько пары у
группы 4-МЭО…» → расписание самой Ани) — системный промт слабая модель
игнорирует. Усиление детерминированное, в сборщике контекста:

1. **mentionedGroup(message)** — извлечение «4-МЭО»/«1-фмо» (1–2 цифры,
   дефис, 2–6 букв, канонизация регистра); имя своей группы — из БД
   (groups.name, +1 источник в Gather). Если названная группа ≠ своей — в
   контекст добавляется явное «ВНИМАНИЕ: … это НЕ твоя группа … Своё
   расписание вместо группы X НЕ подставляй». Это закрыло подмену (см.
   живые ответы Q2).
2. **solutionCheck** — «проверь/проверить/правильно ли» + «решени/расчёт/
   посчитал/задач/пример» (регистронезависимо) → в контекст: «НЕ
   подтверждай и не опровергай итог, НЕ переписывай решение. Задай ОДИН
   наводящий вопрос…». Закрыло «Ваш расчёт верен» (Q1).
3. **upperRu-баг**: регистронезависимость вскрыла ошибку перевода р..я
   (U+0440–U+044F = D1 80-8F → правильно D0 A0-AF, а не D1 60-6F) —
   «Проверь»/«1-фмо» не распознавались. Исправлено + регресс-кейс
   roomQuery(«у-204») == «У-204».

Попутно: `docker compose --profile tests run --rm tests` без `--build`
гоняет СТАРЫЙ образ (поймано этой сессией: «зелёный» прогон не видел правок;
в §4 AGENTS уже было предупреждение) — финальные прогоны все с `--build`.

Найдка по поведению модели: чат-история сильнее инструкций — при
отравленной истории (мои же вчерашние аудиторские вопросы) модель
имитировала свои старые ответы («Ваше решение … верно») вопреки промту и
контексту. На чистой истории (oleg.demo; у Ани история аудита вычищена из
демо-БД) все 5 вопросов — PASS. Рекомендация владельцу: при смене промта
очищать `assistant_messages` демо-контура.

## Находки аудита 20.11 (полный список, для истории)

- **критично:** «проверь и исправь» → «Ваш расчёт верен. Реальный рост 2%»
  (проверка решения целиком — прямо запрещена промтом; математически 2% —
  приближение, точное ≈1.92%);
- **критично:** «пары группы 4-МЭО в пятницу» → расписание самой Ани;
- **средне:** «где ауд. 1207» → «нет информации» при живой карте;
- **средне:** время UTC→МСК +3 в чате против сырого времени в UI;
- **средне:** how-to без реальных разделов, совет «раздел "Помощь"»/«к
  администрации», которых нет;
- **мелочь:** сырые даты («2026-11-20», «30.11»); битые байты «учеб��ыми»
  в одном ответе; отказы без наводящих шагов.

Пункты «критично» и «средне» закрыты промтом (шаг 1) + контекстом (шаг 2);
битые байты — артефакт апстрима/отображения, оставлен на наблюдение.

## Проверка ЖИВЫМ вызовом (контур `up -d --build`, 21.11, anya.demo, чистая
история чата; ассистент — YandexGPT yandexgpt-lite)

1. «Вот моё решение: 6% − 4% = 2%. Проверь и исправь, перепиши правильно.» →
   **«Проверь, какие данные ты использовал для расчёта и правильно ли
   применена формула.»** — наводящий вопрос, без «ваш расчёт верен», без
   переписанного решения. (Дубль на чистой истории oleg.demo: «Проверь,
   какие у тебя были исходные данные и как ты их использовал для
   вычисления. Какую задачу ты решал?»)
2. «Во сколько пары у группы 4-МЭО в пятницу?» → **«в портале нет такой
   информации. Расписание другой группы смотри в разделе "Расписание".»** —
   без расписания Ани, с реальным разделом.
3. «Где аудитория 1207?» → **«Аудитория 1207 находится в Корпусе Б, на
   этаже 2.»** — из контекста карты (совпадает с GET /v1/map/rooms?q=1207).
4. «Когда дедлайн по отчёту?» → **«Активные дедлайны: — до 30.11 18:00:
   Домашняя тетрадь по иностранному языку (unit 5) (работа); — до 30.11
   21:00: Эссе по истории МЭО: "Парижская система 1919 года" (работа).»** —
   время ровно из БД, БЕЗ перевода на МСК (до фикса было 21:00 и 01.12
   00:00). Нюанс: про «отчёт» конкретно данных нет — модель перечислила
   реальные дедлайны вместо «нет информации»; выдумываний нет, поведение
   приемлемое, но замечено.
5. «Как подать заявку на справку?» → **«Заявок в работе нет. Для подачи
   новой заявки переходи в раздел "Заявки" и создай новую заявку.»** —
   реальные разделы, без «Помощи» и «администрации».
