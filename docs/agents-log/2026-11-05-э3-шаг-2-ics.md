## Что сделано

- `src/services/IcsBuilder.{h,cpp}` — чистые функции БЕЗ БД и wall-clock (детерминированы — DTSTAMP задаёт вызывающий): `build()` — VCALENDAR `BEGIN:VCALENDAR / VERSION:2.0 / PRODID:-//para//…//RU / CALSCALE:GREGORIAN` + VEVENT (UID, DTSTAMP, DTSTART/DTEND в базовом формате DATE-TIME UTC `20261104T100000Z` через `toIcsDateTime()`, SUMMARY, LOCATION) + END:VCALENDAR; все строки CRLF (RFC 5545 §2.1); фолдинг 75 октетов сознательно не делается (кириллица многобайтна — риск сломать клиентов, отмечено в комментарии); `escapeText()` — RFC 5545 §3.3.11: backslash первым, затем `;` и `,`, переводы строки (CRLF/LF/lone CR) → один литерал `\n`; `summaryFor()` — предмет + `· ауд. X` + пометка статуса (перенос — с прежней аудиторией «было → стало», отменено, замена преподавателя); `summaryForPlan()` — Консультация/Экзамен/Зачёт/Пересдача по kind (CHECK миграции 0002).
- `src/services/IcsService.{h,cpp}` — вся SQL: `createToken()` — UPSERT `INSERT … ON CONFLICT(user_id) DO UPDATE SET token=excluded.token, created_at=…, revoked=0` — ротация одной операцией (user_id — PRIMARY KEY ics_tokens, «один активный токен» закреплён схемой); токен — `SessionService::generateToken()` (CSPRNG OpenSSL RAND_bytes, 128-бит hex — тот же генератор, что у токена сессии, Р-7); `revokeToken()` — `UPDATE … SET revoked=1 WHERE user_id=$1 AND revoked=0`, идемпотентно; `calendarByToken()` — цепочка: `SELECT user_id FROM ics_tokens WHERE token=$1 AND revoked=0` (нет → found=false → 404; токен и есть аутентификация, 02 §6.1) → `ScheduleService::groupOfUser()` (reuse; staff без профиля — календарь из одного session_plan) → `ScheduleService::eventsOnRange()` на весь горизонт [1970, 3000) — ВСЕ статусы (moved/cancelled остаются в календаре с пометкой SUMMARY) → `planOf()` — session_plan владельца JOIN disciplines по `idx_session_plan_user` → IcsBuilder::build(items, stampNow()). DTEND персональных дат — starts_at + 2 часа (в session_plan нет конца — допущение прототипа, отмечено). Колбэки копируются в обе ветки цепочек `>>` (урок Э2 шаг 1); внутренние лямбды оркестрации захватывают копии — каждая переживает внешний колбэк.
- `src/controllers/IcsCtrl.{h,cpp}` — тонкий (3 маршрута): GET /ics/{token} — 200 `Content-Type: text/calendar; charset=utf-8` или 404 `{"error":{"code":"not_found",…}}` (формат 02 §5.1); POST /v1/ics/token — 201 `{"token": "…"}`; DELETE — 204. POST/DELETE под `"LoginFilter"` (без cookie 401); GET — публичный, path-id {token} — владение по токену, OwnershipGuard не применим (объект ищется не по user_id сессии). SQL в контроллере нет.
- `src/filters/LoginFilter.{cpp,h}` — префикс `/ics/` добавлен в `isPublic()` с обоснованием дословно из 02 §6.1 (строка 601): «Аутентификация всех эндпоинтов, кроме `/v1/auth/login`, `/ics/{token}` (авторизация самим секретным токеном) и `/healthz`»; правило код-ревью не нарушено — приватные POST/DELETE добавлены с фильтром.

## Ошибки ИИ, пойманные и исправленные в ходе (все — компиляцией/тестами контейнера)

1. **Реальный баг RFC, пойманный юнит-тестом:** первый вариант `escapeText()` молча ОТБРАСЫВАЛ lone CR (`case '\r': break` при комментарии «→ \n») — тест `escapeText("a\rb") == "a\nb"` его поймал; исправлено stateful-обработкой с запоминанием предыдущего символа (CRLF → один `\n`, lone CR/LF → `\n`).
2. **`const auto` + mutable-лямбда** — «no match for call» (оператор() mutable-лямбды неконстантный); убран const у локальных `fail/finish/planThenFinish`.
3. **Несоответствие сигнатур в цепочке оркестрации:** `finish` (один аргумент) передавался в `planOf`, чей колбэк — `(bool, vector)`; переписано явным `planThenFinish`; потерянные захваты `userId`/`cb` в двух ветках exception (ошибка компиляции — и та же семья, что двойной move Э2).
4. Ожидания тестов уточнены фактами: строк на VEVENT — 8 (не 7), проверки конца файла переведены на `ends_with` вместо арифметики размеров.
5. Ложная тревога E2E «CR: 0 в ответе» — артефакт чтения через Python text-mode (universal newlines съедает `\r`); повторная проверка сырыми байтами (`open(…,"rb")`) — 29 CR = 29 LF = 29 CRLF, 0 одиночных LF.
