## Диагностика (воспроизведение точного сценария гейта)

- **Сборка и прогон:** одноразовый контейнер `drogonframework/drogon:v1.9.14` (том пересоздан — свежая БД, фикстуры пересеяны `--seed`; сессии dean.demo/dina.demo — прямой INSERT в `sessions`), сценарий гейта дословно: С2-подача (201, id=4, submitted) → **need_info через staff-эндпоинт** `POST /v1/staff/applications/1/status {"to_status":"need_info"}` → 200, sqlite `need_info` → **сообщение Дины** `POST /v1/applications/1/messages` → 201, тело: событие `from_status:"need_info"`, `to_status:"in_progress"`, автор 4 → **проверка возврата: sqlite `in_progress`, последнее событие `need_info -> in_progress автор=4`, GET-карточка `status: in_progress`** — серверное поведение АВТОМАТИЧЕСКОГО возврата воспроизводится как работающее в точном сценарии гейта (лог: `para/docs/agents-log/` — эта запись; вывод команд — в журнале).
- **Вывод по возвратВРаботу:** код возврата работает; false у гейта — из проверки, читающей форму, которой в ответе не было: 201-ответ messages — объект события (`from_status/to_status/…`), поля «статус заявки после сообщения» в нём не было. Исправление — сделать возврат читаемым прямо в ответе.
- **pdfШтамп:** маркер шага 4 (`\320\224\320\225\320\234\320\236` — OCTAL-эскейпы UTF-8 «ДЕМО» из KEYWORDS) есть только в СЫРЫХ байтах; при чтении файла PDF-парсером (октал-эскейпы декодируются в байты, читаемые как mojibake-текст) «ДЕМО» не находится — проверено python-декодированием в этой сессии: raw find octal=185, raw find ascii=374; decoded: «ДЕМО»=-1, **DEMO-FAKE-DATA=189**. ASCII-хвост штампа выживает в любой форме. Исправление — канонический машинный маркер = ASCII.

## Отклонено (с причинами)

- Добавление GET /v1/staff/applications/{id} (карточка заявки для staff) — вне контракта 02 §5.2, гейтом не запрошено; гипотеза «гейт читал статус чужой сессией» не подтверждена.
- Смена кода ответа messages 201→200 — против 02 §5.2 и сценария гейта («сообщение Дины (201)» = true в цепочке).
- Перевод KEYWORDS в hex UTF-16BE (кастомный энкодер поверх libharu) — ломает as-is использование библиотеки; ASCII-маркер решает надёжнее и без кастомизации.
