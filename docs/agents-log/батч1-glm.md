### БАГ 1 — подвал (коммит `d8f3172`)

- **Корень:** footer рендерится ПОСЛЕ закрытия `<main class="shell">`
  (views/schedule.csp:74–76) — у `.footer-top` не было ни max-width, ни боковых
  паддингов.
- **Фикс:** `.footer-top` — `max-width:1200px;margin:auto;padding:0 1rem`
  (сетка как `.header-inner`/`.shell`), в ≥1024px — `padding:0 2rem` (как
  `.shell` десктопа). Бордер-top остался на всю ширину.
- **Проверка:** harness-стенд в /tmp (симлинк static/ + DOM из partials), IAB
  браузер: 360px dark — текст подвала от x=16, соосен контенту main; 1280px
  light — `footerTop` {left:40,right:1240} == `shell` {left:40,right:1240},
  `h1` и `.disclaimer` оба left:72 (замер getBoundingClientRect в странице).

### БАГ 4 — переносы текста (коммит `ef9a666`)

- **(а) таб-бар.** Корень: глобальный `overflow-wrap:anywhere` (строка 11
  app.css) разрешает побуквенный перенос внутри `.nav-link`. Фикс:
  `white-space:nowrap` + кегль `.625rem` (10px; токенов кегля в tokens.css нет —
  шкала app.css) + `letter-spacing:-.01em`; горизонтальный паддинг полосы
  `.primary-nav` 4px→0 (колонка таба 72px при 360); `.nav-link span` —
  ellipsis-страховка для окон <360. Первый вариант с `.6875rem` отсеян замером:
  «Успеваемость» 78.8px > 70.4px колонки (вылезала на соседа) — уменьшил кегль
  до 10px и убрал паддинг полосы.
- **(б) чипы сотрудника.** Корень: `.actions>*{flex:1}` + `overflow-wrap:anywhere`
  сжимали кнопки до 1 колонки по 64px с побуквенным переносом; `nowrap` сам по
  себе недостаточен — каркасный `a,button{min-width:44px}` (строка 11) перекрывает
  automatic minimum flex-элемента, и `flex-wrap:wrap` не переносит (замер: все
  кнопки по 64.5px с переполнением). Фикс: `.staff-actions .button{white-space:
  nowrap;min-width:max-content}`.
- **Проверка (360px, замер в странице):** табы — все `fits:true`
  («Успеваемость» textW 70.5 ≤ 72), высота ссылки 52px (+6px×2 полоса = 64px
  тап-зона); кнопки переходов — `overflowX:0` у всех, ширины 94/188/141/141px,
  flex-wrap перенёс ЦЕЛИКОМ в 2 строки по 2, высота 48px (≥44); скролл
  `scrollW:360 == innerW:360`.

### БАГ 5 — акцентная линия переноса (коммит `20365cc`)

- **Корень:** `.lesson.moved{box-shadow:inset 3px 0 0 0 var(--warning-text)}`
  (строка 35) — `border-radius` контейнера `.schedule-list` без `overflow`
  потомков не клипит: у первой/последней пары прямая линия пересекает дугу углов
  карточки.
- **Фикс:** `.schedule-list{overflow:hidden}` (вариант «overflow:hidden по
  радиусу» из постановки; alternative через pseudo-element не устраняет выход за
  углы без того же клипа).
- **Проверка:** до/после на одной геометрии (карточка с единственной парой —
  как before-accent.png): 4x зум в браузере — ДО линия пересекает верхнюю и
  нижнюю границу; ПОСЛЕ (toggle overflow:inline) — обрезана по границе;
  попиксельный diff снимков (чистый python, PNG-декодер с фильтром Paeth):
  5056 различающихся сэмплов в 50 строках (углы); ПОСЛЕ правки файла — 6x кропы
  углов из свежего скриншота: линия от границы до границы, за радиус не выходит
  (360px dark и 1280px light).

### БАГ 7 — сетка недели на десктопе (коммит `addf062`)

- **Корень:** `#schedule-segment` несёт каркасный `.content-narrow` (720px) в
  обоих сегментах (schedule_week.csp:218, schedule_today.csp:167) — на десктопе
  ~2/3 ширины (720 из 1168 контента shell).
- **Фикс:** в существующем `@media(min-width:1024px)` — `#schedule-segment
  {max-width:1200px}` (ID-скоуп: `.content-narrow` глобально трогать нельзя —
  используется на ~15 страницах; ID-скоуп в app.css — прецедент `#queue .chips`).
  Колонки `.week-columns` растянулись на весь контейнер сами (блочный grid).
  Мобильная вёрстка не тронута: правило только внутри ≥1024px.
- **Проверка:** 1280px — `#schedule-segment` width 1136 (72→1208, вровень с
  контентом shell; было 720), computed max-width 1200px, `scrollW:1280`;
  360px — `maxW:720px` (base-правило), segW 328, `scrollW:360` — без изменений.
