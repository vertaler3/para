## Ошибки/правки ИИ в ходе

- **Лакуна query-фильтров каталога (найдена гейтом, раунд 1):** исполнитель шага 1 сознательно отложил фильтры date/capacity (02 §5.2) «на шаг 2», но в шагах 2–3 они не были закрыты — гейт это поймал как единственный false. Урок: отложенное «с шагом N» из журнала шага должно попадать в план следующего шага явно, а не оставаться заметкой в шапке файла. Исправлено `31bd20a`.
- **«каталог»:false не воспроизводится (раунд 2):** правка раунда 1 по единственной гипотезе не изменила вердикт байт-в-байт; вместо третьего слепого прогона — эскалация владельцу гейта, раскрывшая критерий (три подчка). Фактический прогон подчеков на свежем коде зелёный; причина вердикта false гейта по сводке не установлена — раунду 3 нужен собственный вывод подчика и сырой ответ. Урок: при невоспроизводимом false — сначала критерий и сырой вывод, потом правки.
- **EXPLAIN SCAN при `status IN ('booked','blocked')` (шаг 1):** запрос сетки с IN не использует частичный индекс (SCAN) — сетка шага 1 построена по активным броням `status='booked'` → SEARCH `idx_bookings_active`; отображение блокировок ('blocked') отнесено к шагу 3 и реализовано UNION ALL статус-веток (blocked-ветка — SCAN единичных строк).
- **Коллизия имён Result (шаг 1):** `para::RoomsService::Result` vs `drogon::orm::Result` — типы строк пишутся полностью (практика ScheduleService).
- **Двойной move колбэка в цепочке `>>` (шаг 2):** повторение урока Э2 — success-ветка move'ит cb, error-ветка получает пустой `std::function` → `std::bad_function_call`; поймано тестом, латентные аналоги в `slots()`/`cancelById()` исправлены — все цепочки RoomsService копируют cb.
- **Self-reference цикл рекурсивной цепочки (шаг 3):** `shared_ptr<std::function>`, захватывающий сам себя, держал транзакцию → соединение не освобождалось, E2E зависла; переписано в линейную цепочку из 3 SQL + rowid-SELECT.
- **Fire до коммита (шаг 3):** результат блокировки отдавался 201 до фиксации транзакции (sqlite-SELECT после ответа читал неснятую бронь); переведено на `setCommitCallback`.
- **Окно гонки в create() (low, ревью — НЕ исправлено):** SELECT-проверка пересечения и INSERT не в одной транзакции — параллельные POST с РАЗНЫМИ starts_at, пересекающимися по времени, могут оба пройти (UNIQUE `idx_bookings_active` ловит только одинаковый starts_at; гонка одинакового слота закрыта — исключение БД → 400). Находка ревью в коде этой сессией не применялась (`645eb13` трогал только AGENTS.md); зафиксирована настоящим журналом — решение о правке (транзакция/эксклюзивная проверка) за следующим этапом.
