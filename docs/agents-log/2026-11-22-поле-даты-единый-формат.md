# 22.11.2026 — поле даты: единый формат «22.11.2026» на всех устройствах

Запрос владельца: нативное поле даты (`<input type="date">`) рисует
значение в формате локали ОС — «11/22/2026» (en-US), «22.11.2026» (ru
десктоп), «22 нояб. 2026 г.» (Chrome на Android-ru); текст контролирует
браузер, страницу не спросит. Хотим одинаково везде: «22.11.2026».

## Решение («кнопка + скрытое поле»)

- Инпут остаётся в разметке со всеми прежними атрибутами (id, min/max,
  value, валидация, data-хуки), но становится прозрачным и абсолютным
  ПОВЕРХ своей надписи — клик в любую точку поля открывает системный
  календарь как прежде (`elementFromPoint` в центре = сам input,
  проверено).
- Видна наша надпись `.date-field-view` (дд.мм.гггг) + иконка календаря
  (маска-SVG в CSS). Стили — как у инпутов эталона (те же токены).
- SSR: на расписании текст сразу рендерится из `dayQ` (дд.мм.гггг) —
  без мигания; на брони ставит JS при инициализации (там и так задаётся
  дефолт «сегодня»).
- `app.js`: `syncDateField/syncDateFields` + делегированные
  change/input (переживают htmx-обмен день↔неделя; для расписания
  добавлен вызов и в `htmx:afterSwap`); формат зашит:
  `value.split('-').reverse().join('.')` — без локали.
- Файлы: `views/partials/schedule_today.csp`, `views/rooms.csp`,
  `static/js/app.js`, CSS — через генератор `tools/build_app_css.py`
  (воспроизводимость от 7feaccd проверена — REGEN-IDENTICAL), ключ
  i18n `common.pickDate` ×3 (ru/en/zh) для пустого значения.

## Проверки

- `docker compose --profile tests run --rm --build tests` → ctest 2/2,
  100% (security рендерит обе страницы с новой разметкой; i18n keyset ×3
  согласован).
- Живой контур (`up -d --build`), 412 px (ширина Note): расписание —
  поле «22.11.2026», инпут прозрачный поверх, клик в центр надписи
  попадает в INPUT (системный календарь); смена даты → «25.11.2026» +
  `?date=2026-11-25` + день перезагрузился; бронь — «22.11.2026»
  (дефолт «сегодня»). Скрин 360 px —
  `gui-audit-2026-11-19/64-date-field-unified.png` (вне репо).

## Осознанные ограничения

- Выпадающий календарь остаётся системным (это правильно); ручной ввод
  с клавиатуры в поле заменён выбором из календаря.
- Формат «дд.мм.гггг» одинаков для всех языков интерфейса (владелец
  явно попросил такой формат); если когда-нибудь нужен локальный формат
  en/zh — точка изменения одна: `syncDateField` в app.js.
