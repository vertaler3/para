   пользовательский URL, 03 §5.3 запрещает голые JSON-ошибки на UI;
   задокументировано в шапке контроллера.
3. **Скелетон — только на /applications/new** (каталог грузится fetch-ом);
   список и карточка целиком SSR — скелетона нет (03 §5.1:984 «при
   догрузке», прецедент grades.csp).
4. **Автосохранённый черновик при подаче остаётся в списке черновиков**:
   у студента нет эндпоинта submit СУЩЕСТВУЮЩЕЙ строки (02 §5.2 — submit
   только при POST-создании; PUT только draft) — «Подать» при привязанном
   черновике делает PUT-синк + POST {submit:true} новой заявки; расширение
   API — задача BE-дорожке, не FE.
5. **draft-restore на форме не делался** (03 §4.5.3 упоминает баннер
   «Черновик восстановлен») — постановка экрана его не требует, а честный
   restore требует клиенту знать свои черновики ДО выбора типа (fetch
   ?status=draft) и открывает вопрос «подать существующий черновик»
   (см. п.4) — за пределами постановки этого экрана.
