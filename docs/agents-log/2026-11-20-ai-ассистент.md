# 2026-11-20 — идея 5.19 «AI-ассистент» (ветка `ai_assistent`)

Журнал ведётся по ходу работы (AGENTS.md §5.7). Исполнитель — Claude Code (основная модель), советник и checker — по методу «команда моделей».

## Постановка (промпт владельца, кратко)

Чат-ассистент на дашборде поверх YandexGPT (OpenAI-совместимый endpoint):
- миграция `assistant_messages`;
- `POST /v1/assistant/chat` и `GET /v1/assistant/history` под LoginFilter, вход ≤ 700 символов, rate-limit 10/мин, fail-closed 502;
- контекст — только данные самого пользователя;
- FE-sheet с четырьмя состояниями;
- тесты, Р-запись, правки 01/02 и AGENTS.md;
- коммит и push в `ai_assistent` после каждого шага.

Настройки (URL, ключ, модель, системный промт) — только в локальном `.env`. **Ключ и текст промта в журнал не копируются** (в промпте владельца они были, здесь — `[скрыто]`).

## Шаг 2 — BE: `AssistantService` + тонкий `AssistantCtrl`

- **Роуты** (оба под LoginFilter, path-id нет — всё по user_id сессии):
  - `POST /v1/assistant/chat {message}`, CSRF — автоматически LoginFilter (Р-23);
  - `GET /v1/assistant/history` — последние 20 своих сообщений по возрастанию.
- **Порядок проверок** в контроллере: пусто или не строка → 400 → длиннее 700 кодпоинтов UTF-8 → 400 → лимит 10/мин на пользователя (скользящее окно в памяти; слот учитывается ДО вызова модели) → 429 + `Retry-After` → сервис.
- **Контекст** — только свои данные, через публичные API существующих сервисов:
  - расписание группы на сегодня И завтра (`ScheduleService::eventsOnRange`; «завтра» добавлено ради приёмочного вопроса «что у меня завтра?»);
  - план сессии (`GradesService::exams`, будущие);
  - активные заявки (`ApplicationsService::list` + `DashboardService::isActiveApplicationStatus`);
  - дедлайны: личные + групповые будущие — единственный новый SQL, параметрами;
  - ≤5 ближайших событий ленты news видимой аудитории (`NewsService::feed`).
  - Время — московское (UTC+3). Отмены и переносы помечены («ОТМЕНЕНА», «ПЕРЕНЕСЕНА (было: …)»).
- **fail-closed:** ошибка БД любого источника → 500, частичный контекст модели не уходит. Ошибка модели (сеть, таймаут 20 с, не-200, пустой ответ, не настроено) → 502 `assistant_unavailable`. Тело апстрима не логируется и не отдаётся — в нём служебные id облака.
- **История** пишется парой (вопрос + ответ) одним INSERT и только при успехе модели.
- **Запрос к модели:** `Authorization: Api-Key <ключ>`; `model` — URI; `max_tokens` 500; `temperature` 0.3. Сообщения: системный промт + контекст, затем 10 последних реплик, затем вопрос.
- **Настройки** читаются из окружения на каждый запрос. Значения в кавычках раскрываются сервисом (`docker run --env-file` кавычки не снимает, compose — снимает; работают оба пути).
- **Транспорт** — `drogon::HttpClient` (новых библиотек нет), инъецируемый: тесты подставляют фейк.
- **Проверка** (dev-сервер :8082, `.env` передан `--env-file`; скрипт dev-run.sh обновлён):
  - без cookie: chat 401, history 401; без CSRF → 403;
  - пусто, `{}`, не-JSON → 400; 800 символов → 400 «Вопрос длиннее 700 символов»;
  - 12 подряд: 10× 502 (апстрим 403, см. шаг 0) + 2× 429, `Retry-After: 59`; 700 символов после серии → 429;
  - с локальным фейковым LLM (python, `ASSISTANT_API_URL` → host.docker.internal): 200 `{reply}`. Фейк увидел заголовок `Api-Key …` и model `gpt://<каталог>/yandexgpt-lite/latest`. Контекст Ани: пятница, 2 пары (одна ОТМЕНЕНА), завтра пар нет, 2 дедлайна, 3 события. History вернул пару user/assistant.
- **Находка:** лента news отсортирована по published_at — события в контексте шли не по дате; исправлено сортировкой по event_at.
- dev-build: doctest 175/175, security 119/119, ctest 2/2.

## Фикс (вне ассистента) — объявления в сегменте «Новости»

- Запрос владельца: объявления (`announcements`, `GET /v1/announcements` из Э6) пропали из сегментов «Новости/События» — с фиксов 19.11 они жили только в отдельном сегменте «Объявления». Вернуть в «Новости» одной лентой с новостями.
