## Состояние на вход шага (честно)

Пункт «schedule-ответы дополняются teacher_id» гайда §9а (строка 102) был **уже внесён в шаге 2 Э6а** (коммит `6e043f0`), поскольку -правки `ScheduleService` без включения teacher_id оставили бы пункт этапа незакрытым: `kSelect` выбирает `e.teacher_id` (ScheduleService.cpp:25), `eventJson` отдаёт `e["teacher_id"] = optInt64(...)` (строка 65, NULL → null), два «мёртвых» CHECK_FALSE в schedule_service_test заменены на CHECK со значениями (today-кейс: «История России» → 4; changes-кейс: substituted-событие 11 → замещающий 1). Контроллер трогать не потребовалось (ScheduleCtrl тонкий — данные идут через ScheduleService::today/week/changeList), ICS (IcsBuilder/IcsService) не тронут.

1. teacher_id в ответах — «сырое» значение колонки (teachers.id из 0002); people-адресация (Р-15: teacher_id + kPersonIdOffset=1000) — забота FE/потребителя, задокументировано в комментариях eventJson и журнале шага 2.
