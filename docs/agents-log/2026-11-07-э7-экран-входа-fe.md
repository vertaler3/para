## Ошибки по ходу

- **app.js не был подключен нигде**: каркасный head.csp подключает только
  CSS, а partials его не подключают — живая проверка показала, что тап по
  демо-роли ничего не делает (script 404 бы не дал — его просто не было
  в разметке). Исправлено подключением `<script defer>` на уровне
  страницы (как в design-drafts); вопрос вынесен в результат задачи:
  следующие экраны должны повторять это (или вынести в head.csp).
- **Сетевой сброс во время запроса**: первый вариант finally возвращал
  кнопку в enabled при активном офлайн-режиме (navigator.onLine может
  остаться true при упавшем fetch) и портил восстановление после
  возврата сети — поймано стаб-тестом, исправлено (флаг wentOffline,
  data-was-disabled='0' — восстановление каркасом после сети).
- IAB-бэкенд не доставляет реальных кликов в страницу (probe: 0 событий)
  — живые тапы заменены синтетическими событиями через реальный DOM
  (те же обработчики app.js); координатный ввод недоступен в этой среде.

## Правки по ревью (раунд 1, 07.11 — тем же amend-коммитом)

Ревью вернуло 3 замечания (все low, verified); разбор и статус:

1. **too_many_attempts без отсчёта (app.js vs 03 §4.1/§5.3) — ИСПРАВЛЕНО.**
   Обработчик 429: клиент читает `Retry-After` (BE отдаёт всегда —
   AuthCtrl.cpp:62; паузу ведёт серверный LoginLimiter 15→30→60… —
   клиент не дублирует модель), запускает отсчёт на disabled-кнопке
   «Подождите N с» (03 §4.1 дословно), сообщение у формы —
   «Слишком много попыток входа. Подождите {N} секунд и попробуйте
   снова.» (03 §5.3); без заголовка — стартовая пауза 15 с (03 §4.1).
   По истечении кнопка возвращается в «Войти» (если сеть есть; при
   офлайне — остаётся на управлении applyOffline). Повторная отправка
   в отсчёте заблокирована (guard по таймеру + disabled). Стаб-тесты:
   429 с Retry-After: 2 (подпись/сообщение/блокировка/разблокировка),
   429 без Retry-After (15 с, прогон полного отсчёта), 429+офлайн
   (отсчёт завершается, кнопка остаётся disabled до возврата сети).
   Живой прогон в браузере с мок-429 (Retry-After: 2): подпись
   «Подождите 2 с», повторный submit не проходит, после отсчёта
   «Войти» и кнопка активна.
2. **Офлайн-кнопка без helper-текста (app.js applyOffline vs 03 §5.4)
   — ИСПРАВЛЕНО.** applyOffline теперь поддерживает атрибут
   data-offline-label у [data-network-action]: на время офлайна подпись
   кнопки заменяется на его значение, исходная запоминается в
   data-was-label и возвращается после reconnect (у элементов без
   атрибута — прежнее поведение с title). Кнопке входа задан
   data-offline-label="Нужна сеть для входа" (03 §5.4 дословно;
   login.csp). Согласовано с busy-состоянием: при сетевом сбросе во
   время запроса подпись «Войти» восстанавливается ДО applyOffline
   (в data-was-label попадает «Войти», а не busy-подпись «Входим…»);
   в finally офлайн-ветки data-was-label также фиксируется. Стаб-тесты:
   офлайн при загрузке (helper-текст, was-label), сброс в запросе
   (helper-текст + was-label «Войти»), offline-событие в середине
   запроса с ошибкой ответа (helper + восстановление после сети),
   429+офлайн. Живой прогон 401 после правок — без регрессии
   («Неверный логин или пароль», кнопка восстановлена).
3. **Редирект на «/» без маршрута (app.js:181 vs AuthCtrl.h) — НЕ
   ИСПРАВЛЕНО (вне владения FE), причина ниже.** Обработчиков страниц
   у FE нет (src/controllers — владение BE-дорожки, AGENTS §5.8,

   (успех 200 → location.href="/") и флоу 03 §4.1 («После входа →
   „Сегодня"», таб «Сегодня» — href="/"). Маршрут «/» появляется
   следующим экраном этой серии (главный экран); до этого успешный
