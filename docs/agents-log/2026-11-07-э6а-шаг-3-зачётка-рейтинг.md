## Находки шага

1. **Пропущенный ключ JSON** (пойман юнит-тестом): в GradebookService поле `works` копилось в totalWorks, но НЕ ставилось в объект дисциплины (`d["works"] = works` отсутствовало) — Json::Value при чтении несуществующего ключа возвращает null → as<int64_t> == 0. Диагностика осложнялась тем, что значение из SQL (r["works"]) было верным — проверены и по имени, и по индексу; ловушка «читается null молча» — не путать с проблемой drogon-слоя.
2. **limit-контракт**: `maxRows=0` («без ограничения») внутри цикла рейтинга обрезал список до нуля (`size >= maxRows → break` при 0>=0) — юнит-тесты с явным limit=0-вызовом это не ловили, поймано E2E (rating пустой при живом SQL); исправлено `maxRows > 0 && ...`, зафиксировано тестом.
3. **Пересборка сервера обязательна для E2E**: после фикса `para-tests` пересобирался, а бинарь `para` — нет (E2E показывал старое поведение при зелёных юнитах) — перепроверка после полного `make para` обязательна, отмечено для будущих шагов.
4. Итог дисциплины = СУММА всех строк (постановка шага): при появлении пересдач attempt≥2 баллы обеих попыток сложатся (поведение зафиксировано тестом); «лучшая попытка» — отдельное решение, если жюри/гейт затребует.
