## Сделано

- **`src/services/NotificationsFeedService.{h,cpp}`** — вся SQL ленты/пометок параметрами (`$N` по порядку появления в тексте — урок Э5): `feed()` — плоская лента текущего пользователя `ORDER BY created_at DESC, id DESC LIMIT 21` (20 на страницу — константа как у Announcements; 21-я строка — детектор следующей), query 02 §5.2: `unread=1` → `AND read_at IS NULL`, `type` → словарь CHECK 0004 через `notifyTypeFromString/notifyTypeName` (единый словарь с NotifyDispatcher; вне словаря → BadRequest/400), `cursor` → СОСТАВНАЯ пагинация `(created_at, id)`: сервис перечитывает `created_at` строки-курсора (SELECT скопирован по user_id — чужой/несуществующий курсор → BadRequest, содержимое чужих строк не раскрывается), условие страницы `created_at < $c OR (created_at = $c AND id < $cid)`. `markRead(userId, id)` — условный UPDATE `read_at=strftime('now') WHERE id AND user_id AND read_at IS NULL` (идемпотентно: уже прочитанное → 0 строк → AlreadyRead → тот же 204; read_at — серверное время, не строка клиента; user_id в WHERE — скоуп в самом запросе 02 §6.3 п.2, guard не замена). `markAllRead(userId)` — тот же UPDATE по user_id, возвращает число помеченных (0 — уже всё прочитано, тот же 204). Поля строки: id/type/title/body/deep_link/read_at/created_at (TEXT NULL → JSON null); тело 200: `{"notifications":[…],"next_cursor":id|null}`.
- **`src/controllers/NotificationsFeedCtrl.{h,cpp}`** — тонкий, 3 роута под LoginFilter: GET `/v1/notifications` (парсинг query, мусорные unread/cursor → 400, стиль upcoming/days), POST `/v1/notifications/{id}/read` — **OwnershipGuard::check(Table::Notifications) ДО пометки** (Own → 204-цепочка; NotFound → 404 not_found; Forbidden → 403 forbidden «Доступ только к своим данным» — дословный пример 02 §5.1; Error → 500 fail-closed), POST `/v1/notifications/read-all` → 204. Успешные ответы — `api::jsonResponse` (emitUTF8 + `X-Para-Round: e6-gate-r2`, правки гейта Э6 р1). Роуты не конфликтуют: read-all/settings — статические сегменты 3-го уровня, `{id}/read` — 4-й (сверено E2E).

## Границы шага и заметки для следующего раунда гейта

- **Срочность переноса для гейта:** `isUrgentSchedule` = 0 ≤ starts−now ≤ 24 ч (NotifyDispatcher.cpp:183-196). Тело-пример переносит event 9 на **2026-11-08T10:00:00Z**: для прогона гейта в окне 07.11 10:00 UTC — 08.11 10:00 UTC перенос СРОЧНЫЙ (тихие часы не задерживают — дельты 1/1 гарантированы при любом времени суток); до 07.11 10:00 UTC и после 08.11 10:00 UTC перенос не-срочный — дельты 1/1 сохраняются, ЕСЛИ гейт идёт вне тихих часов 23:00–07:00 UTC (день → Sent сразу); единственное окно дельт 0 — гейт позже 08.11 23:00 UTC (не-срочный + тихие часы → дайджест).
- **Группировка по типам** — за FE (лента плоская, см. выше); `?unread=1` и `?type=` дают FE данные для бейджа и вкладок без серверной группировки.
- Коммит шага не трогает `static/`/`views/` (FE-дорожка), `sql/`, `main.cpp` и общий `api::errorResponse`.
