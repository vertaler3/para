## Разбор

- После правок раунда 1 в рейтинге Ани оставалось ровно ОДНО полное ФИО — её СОБСТВЕННАЯ self-строка («Соколова Анна Игоревна», average null): мой рейтинговый SQL был LEFT JOIN grades — студенты без оценок попадали в список с average null, включая запрашивающего. Гейт-чек «рейтинг Ани — ни одного полного ФИО» находит его.
- Чеки Марка и Ани согласуются в одну модель только при семантике «рейтинг = студенты СО СРЕДНИМ БАЛЛОМ» (02 §5.2 «рейтинг … по среднему баллу»): у Марка «его строка с полным ФИО» (он оценён — self-полная), у Ани «ни одного полного ФИО» — её строки в рейтинге нет вовсе (нечему показывать), остаётся «М. Ливанов». Прежнее расширение «включать без-оценочных с average null в конце» было произвольным и давало self-полное ФИО в ответе.

## Исправления (para/)

- **`src/services/RatingService.cpp`** — `LEFT JOIN grades` → `JOIN grades` (INNER): студенты без оценок не попадают в рейтинг; `averageOf` упрощён (max_sum не NULL; max<=0 — null); ORDER BY без `IS NULL`-ветки. Комментарий у SQL — обоснование гейт-чеками.
- **`src/services/RatingService.h`** — контрактная шапка: «РЕЙТИНГ = студенты СО СРЕДНИМ БАЛЛОМ (гейт Э6а раунд 2)…».

## Отклонено

- Убирать полное ФИО из self-строки Марка (маскировать всё) — противоречит гейт-чеку «рейтинг Марка — его строка с полным ФИО» и 02 §5.2 «полное имя — только в строке самого пользователя».
